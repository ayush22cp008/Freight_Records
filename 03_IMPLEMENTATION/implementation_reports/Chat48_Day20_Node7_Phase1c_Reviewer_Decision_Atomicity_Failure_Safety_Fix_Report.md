## 1. Objective

Implement a failure-safe, atomic Postgres transaction boundary for Reviewer decisions (Approve/Reject) to guarantee that failures during the operation do not leave the applicant in a broken or partially committed state.

---

## 2. Implementation Details

- **RPC Created**: `012_reviewer_decision_rpc.sql`
- **Function**: `process_reviewer_decision(p_identity_id UUID, p_action TEXT, p_rejection_reason TEXT)`
- **Route Updated**: `src/app/api/admin/review/route.ts`

**Transaction Scope (RPC):**
The newly introduced RPC automatically runs inside a Postgres transaction. It sequentially:
1. Validates the target identity is `PENDING`.
2. Locates the current `PENDING` evidence strictly tied to the identity.
3. If `REJECT`: Updates evidence to `REJECTED`, identity to `REJECTED`, and inserts a `reviewer_decisions` audit row.
4. If `APPROVE`: Updates evidence to `APPROVED`, identity to `VERIFIED`, inserts an audit row, and creates the business `drivers` or `companies` record.
5. If any operation fails internally, the entire RPC aborts and throws an exception, safely rolling back all changes and keeping the applicant `PENDING` for a clean retry.

**API Route Refactor:**
`src/app/api/admin/review/route.ts` was refactored to replace the sequence of unbatched `supabaseServer` calls with a single call to `supabaseServer.rpc('process_reviewer_decision')`. It handles recognized RPC exceptions (like "Identity not found") and returns the appropriate HTTP status codes.
